# H1E microphone-only VAD evidence boundary — 2026-10-16

The retained native exports have no `EnergyChannelVAD` symbol. They do have a `VoiceEnergy` getter: wrapper `0x0101fa9c` calls the function pointer in RAM slot `0x00080e70` with `r0=0x4009ffd0` and an output pointer in `r1`. Caller `0x01020d9c` initializes a 32-bit local and, on success, caches its low byte at state `+1`. This is a real static wrapper/caller in the audited 6.3.0 image, but `VoiceEnergy` is only a candidate energy measurement; its name does not prove voice detection or a microphone route.

The retained lifecycle audit found no executed-code registration/call to `0x01020d9c`. The apparent address at `0x01021618` is switch-table data; the periodic callback registered by `0x01021168` is `0x01020f18`. Therefore the evidence does **not** show `VoiceEnergy` being executed or a passive cache sample being available. Calling its wrapper would add a DSP query. Provider serialization, output contract, route, freshness, and side effects are not qualified, so that query must not be assumed safe.

The scheduled reader already observed is `RefChannelVAD`, wrapper `0x0101fb68` with `r0=0x40000090`, called by poller `0x01020b58` and cached at state `+4`. Existing 393992 playback receipts recorded raw `1` in 15/65 active speaker-playback samples, 0/20 in a quiet-before window, and 0/55 after playback ended. This is a temporal association with those playback trials only; microphone-only response, route, and general voice meaning remain unproven.

## 17 October: controlled microphone-only speech trial

The user reported speaking for about 20 seconds during an independently started native recording. Start verification was acknowledged, the active recording was confirmed privately, and stop was acknowledged with the device returning idle. F11A only sampled the existing getter; it does not start native recording. A subsequent normal library download completed and persisted one recording locally. The recording and download remain private; this note contains aggregate measurements only.

The earlier no-speech Windows capture separately verified the exact H1E endpoint at 48 kHz stereo. That capture was closed before this native recording; its settings are not the native file format. Analysis of the retained 35.6-second, 16 kHz stereo native recording found voice activity on channel 0 during seconds 1–21 (maximum window RMS −22.69 dB), followed by quiet during seconds 22–35 (window RMS −67.3 to −61.6 dB). Channel 1 remained low across the analyzed windows (−67.1 to −64.7 dB RMS).

During the same trial, 109 F11A snapshots all returned raw `0`; native state was `5`, getter status was `0`, and every observation was valid. Thus, captured microphone speech did not produce a nonzero `RefChannelVAD` value in this trial. This is a negative result for this specific setup and interval, not a universal VAD conclusion. The user also confirmed no speech occurred in the two earlier 55-second passive/UAC intervals (297 and 261 samples, respectively); their all-zero samples are not negative microphone-voice tests, and the low UAC channel levels do not imply a capture failure in the absence of speech.

**Next condition for broader qualification:** this single microphone-only comparison is complete. Any repeat should use the existing F11A snapshot path with controlled quiet and speech intervals and no speaker playback. Do not add a getter for that comparison. Before considering `VoiceEnergy`, first retain an authoritative provider contract covering callback serialization/ownership, output width and status behavior, route/meaning, freshness, and side effects; then assess a separate narrowly scoped query.
