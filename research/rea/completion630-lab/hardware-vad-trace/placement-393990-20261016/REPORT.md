# 393990 VAD compatibility and placement contract

Status: conditional source-integration contract for `6.3.6_vectors001` / packed version 393990. This is an offline source and byte audit. It does not compose an image or qualify placement, boot, flash capacity, or hardware behavior.

The current SYS is `abff684071be35f29286010c13e27f8af51de364efbaedffdd12bb6e85ebd360` (1,237,504 bytes). Its retained base is `b338e4d5e7d456dd2b7a0048bb8e2c338e2464ad25029267b5e46cb4ad880c2f`. I compared every old VAD sparse-hunk preimage against the current 393990 bytes: eight of ten match. The constructor and poll hunks remain byte-compatible. The two mismatches are the response/parser hook sites already changed by the current vector console: `0x0103907a` contains `07e01395`, which decodes to `console630_response_hook` at `0x0112baa0`; `0x0103a996` contains `07e06188`, which decodes to `console630_parser_hook` at `0x0112ba58`. The old response/parser hunk bytes must not be applied. The machine-readable details are in [COMPATIBILITY-393990.json](COMPATIBILITY-393990.json).

The compatible design is a small F11A-only dispatcher at the C entry points expected by the existing `console-hooks.S` wrappers. It handles only command `0xf11a` through VAD. Every other command forwards the same arguments to the current `console630_parse` (`0x0112b70c`) or `console630_response` (`0x0112b800`) and returns the current handler's result unchanged. This keeps the current F117 vectors/help/version/uptime behavior, F118 upload, F119 restore, and other router commands, including F114. The dispatcher should link the current entry points under distinct aliases and retain the existing wrapper ABI. Replacing the old bundled `console630_f11a.c` with this dispatcher avoids importing the old 393988 console behavior.

The current console owns a declared 4 KiB region at `0x0112b000`; its live module is 3,189 bytes, leaving 907 bytes inside that reservation. The older full VAD module has 2,684 bytes of `.vad_text` at the hypothetical `0x0112f000` base and therefore does not fit that tail. Removing the measured old parse/response bodies and formatting/division helper symbols accounts for about 834 bytes, leaving roughly 1,850 bytes before adding the new forwarding dispatcher. That is symbol-size arithmetic, not a fresh link or proof that console slack is assignable. It does not establish a no-growth implementation.

The old module’s hypothetical range begins at the end of the pinned parser/upload/restore reservations, but that linker example is not a current VAD reservation. Its previous integration appended 6,272 bytes, producing a 1,243,776-byte SYS.
