# Combined source review: native VAD observation candidate

## Scope and verdict

I verified the handoff file SHA-256 as `23988b60eebe8ecffaa0b0aa7ba3a11c363d0ff4beba03e01aedc44f4724665e` and recalculated all 19 listed hashes; all match. This review uses that pinned snapshot only. No source outside the handoff was inspected, and I made no firmware, application, Git, hardware, or test changes.

**Verdict: suitable to continue source-only wrapper/parser candidate construction, with the native object loader kept absent or stubbed until the lifetime and readiness contract is closed.** The portable core's unclocked semantics and the SDK's strict 32-byte parser are internally consistent for reporting the last successful native caller word. The current binding is an injection seam, not an installable binding: it has no object loader, no one-argument native replacement wrapper, no handler hookup, and no qualified target synchronization. The command and data must remain described as tentative telemetry; they do not establish voice presence, DSP freshness, or channel identity.

## Findings

1. **State 5 plus a second slot read is not a lifetime guarantee.** `vadt_binding.h` explicitly leaves the loader unconnected because the current constructor publishes before zeroing and its failure path frees before clearing slot `0x852c0` (lines 21-29). The proposed delayed publication and detach-before-free encodings are isolated assembly checks, not applied image changes (`lifecycle-followup/lifetime-fix/REPORT.md:5-9,58-64`; `CONTRACT.md:23-45,127-129`). The constructor still publishes before it writes `object+2` and the binding pointer at `+8` (`CONTRACT.md:128`). The retained object audit covers 13 direct users and finds no direct access to the proposed tail, but it does not recover successful teardown, indirect/ROM retention, or all lifetime paths (`object-tail-audit/REPORT.md:11-39`).

   The packet does not establish that byte `object+0 == 5` is a monotonic “fully initialized and never freed” state. It is copied out as an uninterpreted native state byte, and retained users read or write that byte (`CONTRACT.md:103-107`; `object-tail-audit/REPORT.md:15-27`). Even if the reported constructor call precedes `sugr_app`'s main loop and no retained direct free follows state 5, those facts support a readiness heuristic, not an object lease: the Jensen reader is in `usbiap2`, a separate task path, and the packet does not show that it cannot run during constructor failure or prove all later frees absent (`command-binding/REPORT.md:44-48`; `object-tail-audit/REPORT.md:33-39`). Re-reading the slot catches some replacement races, but a free after the second read remains possible; allocator reuse can also make a stale pointer compare equal again.

   **Minimal closure:** keep `load_object` absent until there is either a lifetime mechanism shared with every destroy/free path, or evidence that the object is fully initialized before the command path can run and cannot be freed/reused while it is read. State 5 and slot revalidation may be additional checks, not substitutes. If the latter lifetime premise depends on “no free after state 5,” pin the state transition and all teardown paths in source evidence.

2. **The proposed PSR guard is a same-core mask, not established task exclusion.** The isolated primitive saves PSR, clears IE, and restores the saved value with `memory` and `cc` clobbers (`vadt_csky_guard.c:18-30`). The context report ties vector slot `+0x58` to the copied scheduler switch and shows a write of `1` to `0xe000ec08`, but no read or symbolic register definition (`target-scheduler/REPORT.md:7-19`). The S802 manual makes the TSpending/vector-22 interpretation plausible, while the exact `0xe000ec08` mapping, target core/VIC, and explicit IE gating of TSpending remain unresolved (`primary-mask-contract/REPORT.md:5-11`). Thus the guard's source shape is acceptable for an isolated C-SKY candidate, but do not rely on it as a qualified reader/free or reader/writer lock.

   The alternative bounded seqlock read is useful for coherence: `vadt_snapshot` makes at most three attempts and returns BUSY without spinning (`vadt_core.c:84-123`). It still needs a valid object lifetime, naturally aligned/atomic 32-bit accesses, and target-appropriate ordering. The C99 fields are `volatile`, while the default `VADT_CPU_BARRIER` is only a compiler barrier (`vadt_core.h:32-43`; `vadt_core.c:11-14`). Do not present that as portable thread synchronization. A source candidate should require an explicit target barrier or clearly constrain the candidate to a verified same-core execution/guard contract. Sequence equality is a coherence check, not sample identity; 2^31 completed writes can return the even sequence to the same value during one read, an ABA limit.

3. **The current binding is not callable directly at the native getter call site.** The original getter ABI is correctly modeled as one `uint32_t *` argument and an `int32_t` status (`vadt_binding.h:36-37`), and the implementation calls it once, passes the same pointer, copies the word only on status 0, and returns the status unchanged (`vadt_binding.c:10-29`). But `vadt_binding_poll` itself takes three arguments (`ops`, getter, and word; `vadt_binding.h:52-54`), while the native call at `01020b62` supplies only the caller's pointer (`CONTRACT.md:38-56`). A one-argument wrapper/trampoline and its actual call displacement do not exist yet (`CONTRACT.md:39-45`). Build that wrapper as a separate candidate and inspect its target disassembly against the original call-site register, stack, and return-status contract before any image integration.

4. **The appended tail is bounded in the retained direct-user audit, but layout and allocation are not qualified.** The audit finds no retained direct access to `object+0x40..+0x5f` and identifies another same-wrapper 0x60-byte allocation, which supports source-level feasibility (`object-tail-audit/REPORT.md:5,29-39`). It does not prove 0x60-byte allocation success or base alignment at runtime (`object-tail-audit/REPORT.md:35-46`). In addition, the header asserts only total size 32 (`vadt_core.h:32-43`); the contract relies on every field landing at fixed four-byte offsets (`CONTRACT.md:60-72`). Add C99-compatible `offsetof` assertions for the tail fields and make the loader reject a misaligned base before treating it as `vadt_telemetry_t`. Runtime allocator success/alignment remains a separate qualification item.

5. **The command and SDK codec are acceptable as a tentative byte contract.** The exact frozen fallback audit finds `f11a` unsupported along the retained custom-to-stock chain, with no alias on that route; it does not sweep every 16-bit ID or determine whether the common transport serializer adds a byte (`namespace-proof/REPORT.md:5-18,27`). The SDK parser enforces the unclocked 32-byte contract, rejects age flags/nonzero age and malformed status tails, and preserves the sample/status distinction (`sdk-codec/REPORT.md:21-42`; `packages/jensen-protocol/src/native-vad-observation.ts:43-82`). Keep it unexported and unwired as reported. Before integrating a response handler, settle the serializer's final on-wire body length and exercise the one-byte malformed-request error convention at the native response boundary; the strict SDK parser intentionally rejects that one-byte error (`command-binding/REPORT.md:17-21`).

   One telemetry wording point should be explicit in the candidate contract: `vadt_binding_poll` calls the getter before trying to load the object, and a failed load drops that attempt from the counters (`vadt_binding.c:13-27`; `CONTRACT.md:118`). Therefore `attemptedReads` means attempts recorded while the tail was available, not necessarily every native getter call since startup.

## Acceptance boundary and remaining evidence

The core's success/failure handling, sticky sample flag, raw-zero handling, unclocked reply, and bounded BUSY behavior are suitable to reuse for the source candidate under the documented single-writer and valid-storage assumptions (`vadt_core.c:35-82,84-123,148-212`). The SDK parser is suitable as a private codec candidate. The saved-PSR guard is suitable only as an isolated target-specific primitive candidate. The binding and `f11a` handler are not accepted as connected source integration until the one-argument wrapper, loader/readiness/lifetime decision, and exact response framing are written and reviewed.

The handoff reports 118 host core checks, 66 SDK tests and five actual C-to-SDK vectors; those are host/source evidence only. It reports no generated target image, no installed-image attestation, no live command, and no physical VAD. The raw word must continue to be labeled as the native caller's word after getter success. No age, DSP freshness, voice boolean, or physical channel mapping follows from this source.

The user's new working-day gate remains in force: no hardware test or qualification, firmware flash/update, reset, reboot/power cycle, or teardown is authorized until a new explicit OK. Source candidate construction and offline software work may continue within the boundaries above.
