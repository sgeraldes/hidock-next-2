# Native integration addendum

Review date: 2026-10-13. This addendum supplements `REPORT.md`; it does not change the earlier 19-file snapshot. Paths beginning `hardware-vad-trace/` are relative to `research/rea/completion630-lab/`.

## Decision

Conditional offline source integration is suitable for the native poll wrapper, parser core, strict 32-byte response core, and the seven-hunk late-publication constructor candidate. The conditions are explicit: the candidate uses the normal C-SKY callee-save ABI for `r4-r7`, the observed single-startup path, and an injected reader. The current one-argument response shim and production-shaped loader are still being authored and have not been reviewed here. No fake reader should be linked as a production binding.

This is approval to continue isolated source work only. It is not approval to link or install an image, and it is not target qualification. The loader must have a real lifetime contract before it can return a usable object. The native response route must also establish that initialization has selected one of the source-visible framing states. The working-day hardware gate in `hardware-vad-trace/cache-bridge-candidate/WORKING-DAY-CONSTRAINT.md` remains in effect: no device connection, hardware test, firmware update, reset, reboot, power cycle, or teardown without new explicit user authorization.

## Poll call ABI

At `01020b58`, the caller puts `&local_word` in `r0` (`SP+0x14`), initializes that word to zero, and calls `0101fb68` at `01020b62`. After the call, it reloads `r3` from a literal, compares the returned `r0` status, and reloads the registers used on its later paths. The successful path reads the same `SP+0x14` word. I found no use of the old `r1-r3` values or condition flags after the call. This closes the native-poll report's post-call uncertainty at `hardware-vad-trace/native-poll-candidate/REPORT.md:107` for this callsite only; the bounded evidence is `research/rea/protocol-depth630-lab/audio-host/native-extra/01020b58.tsv:4-25`.

The candidate `h1e_vad_native_poll_bridge(uint32_t *native_word)` therefore matches the one-argument call shape: the output pointer enters in `r0`, and the native status returns in `r0`. Its C-SKY disassembly passes the pointer through and returns the status unchanged (`hardware-vad-trace/native-poll-candidate/REPORT.md:60-73`). `vadt_binding_poll` invokes that getter once, with the same caller pointer, before entering the telemetry guard; it preserves the native status even if the loader cannot supply a tail (`hardware-vad-trace/native-poll-candidate/REPORT.md:91-94`). This does not waive the ordinary callee-save requirement for `r4-r7`, nor does it establish an allocated bridge address. The sample hook address `0x0112c000` in `hardware-vad-trace/native-poll-candidate/REPORT.md:77-83` collides with `.upload_text` in the frozen `firmware/restore-build393988/generation-restore4/module.ld`; it is an encoding example only. Recompute the `bsr` after selecting and linking a real, non-overlapping placement.

## Constructor publication and lifetime

The early-reader audit now resolves the observed startup ordering. `01032e70` calls `01021024`, registers `01021168`, completes initialization, and only then enters the event loop. The known state-machine routes to `01020b58`, `01020f74`, and `0102100c` occur after constructor return; no executed direct or scheduler route to `01020d9c` was found (`hardware-vad-trace/lifecycle-followup/early-reader-order/REPORT.md:3-16`). The delayed-publication candidate must still replace the constructor's own `010210de` slot reload with `mov r3,r7`; otherwise the constructor dereferences the still-null global slot while preparing its GPIO call (`hardware-vad-trace/lifecycle-followup/early-reader-order/REPORT.md:7,32-34`). With that edit, the evidence is enough to proceed with an offline candidate for the retained startup path; it does not require proving the absence of every opaque ROM or interrupt path first.

The private pointer in `r7` crosses the zeroing wrapper, GPIO lookup, logging calls, and the indirect GPIO method. The wrapper's visible instructions do not write `r7`, but its final indirect target and the GPIO method body are unresolved (`hardware-vad-trace/lifecycle-followup/early-reader-order/REPORT.md:28-30`; `hardware-vad-trace/lifecycle-followup/late-publication/REPORT.md:35`). Treat normal C-SKY `r4-r7` preservation as the explicit source-candidate assumption. Before a final image link, either confirm the relevant callees preserve that ABI or spill and reload the private pointer around any callee that does not. This is a bounded ABI check, not a reason to demand absolute absence proof for opaque calls before offline source work.

The production loader remains gated on object lifetime. A null check, state byte 5, and a second slot read do not prevent a free or replacement after validation; an ABA replacement is also possible. The bounded snapshot seqlock can return `BUSY` instead of spinning, but it validates payload consistency only after dereferencing the tail. It cannot protect the tail's lifetime. The loader must establish that the object cannot be freed or replaced for the entire guarded access. The constructor proposal removes its own failure-path free-after-publication and the observed startup path's early readers, but the retained evidence does not establish successful teardown, every free/replacement path, global constructor serialization, or exclusion of asynchronous/indirect users (`hardware-vad-trace/native-poll-candidate/REPORT.md:101-108`; `hardware-vad-trace/lifecycle-followup/late-publication/REPORT.md:45-49`; `hardware-vad-trace/lifecycle-followup/early-reader-order/REPORT.md:20-34`).

`hardware-vad-trace/native-poll-candidate/vadt_layout_check.h` asserts all eight field offsets, a 32-byte telemetry struct, and the `object+0x40` tail ending at `object+0x60`. A production loader still needs to reject a null slot, check pointer-addition overflow and four-byte tail alignment before any word access, and return success only while the lifetime condition above holds. These source assertions do not qualify that the allocator returns a 0x60-byte object or an aligned base. The loader being prepared behind a conditional-integration macro is in progress, not accepted by this review. The guard masks same-core interrupts; it does not prove exclusion of another task, core, or DSP writer, and the telemetry core's default barriers are compiler-only. Do not infer C99 `volatile` thread safety or stronger CPU/DSP ordering from the source. The getter result's meaning is also unqualified: this path records the native caller's word, not a verified VoiceEnergy or speaking signal.

## Parser, response ABI, and framing

The parser candidate has the native three-argument shape. The shared parser checks the command, pending command, exact one-byte request, version, declared length, and fragment state before it writes only `head[8..9]` (`hardware-vad-trace/native-frame-candidate/REPORT.md:18-28`). Its pointer extent checks are NULL-only and its tests derive frame offsets from the same macros as the code. Keep those as explicit dispatcher-contract assumptions and independently pin the offsets before route integration (`hardware-vad-trace/native-frame-candidate/REPORT.md:82-90`).

The response core currently takes three arguments, while the native response hook takes one. The separate one-argument response shim is being implemented and is not reviewed or pinned in this addendum. Both parser and response must route `0xf11a`; the frozen hook currently routes only `0xf117`-`0xf119` and sends `0xf11a` to the native fallbacks (`hardware-vad-trace/command-binding/response-framing/REPORT.md:20-29`).

Keep the response callback body at exactly 32 bytes. The endpoint-helper audit binds the serializer divisor to RAM halfword `0x867d6`: the visible successful `usb_iap2_drv_init` path writes 64, another visible writer stores 512, and the non-mode-1 body capacity is `0x2000-0x0c=8180` bytes. Both visible initialized geometry values leave `L=12+32=44` unextended; mode 1 skips the extension. The same halfword bounds endpoint read chunks (`hardware-vad-trace/command-binding/response-framing/endpoint-helper-binding.md`, “Exact helper contracts”, “Visible initialization and stores”, and “Framing consequence and limit”). This makes strict 32-byte framing source-consistent after either visible setup path. It does not prove which value is active on a live connection, that the Jensen route runs one of those setup paths before it can reply, or that there are no runtime writes through an unresolved alias. The response core's capacity check is enough for 32 bytes in the visible non-mode-1 path; mode 1 does not append. So the source candidate can stay exactly 32 bytes, while a target-wide wire claim remains conditional on the actual startup/response route. Do not add a manual pad or the native 12-byte header in the callback (`hardware-vad-trace/command-binding/response-framing/REPORT.md:16-29,42-44`).

## Placement and remaining gates

The frozen linker script places `.text` at `0x0112b000` with a 4 KiB limit, `.upload_text` at `0x0112c000` with a 4 KiB limit, and `.restore_text` at `0x0112d000` with an 8 KiB limit, ending by `0x0112f000` (`research/rea/completion630-lab/firmware/restore-build393988/generation-restore4/module.ld:1-22`). The poll candidate's illustrative `0x0112c000` entry collides with the existing upload section. The late-publication candidate's `0x01122100` stub is also only illustrative: it is beyond the baseline image end `0x01122040` and lies in the frozen append-layout interval before the fixed `.text` placement; it is neither allocated nor approved. No address in either example may be carried into an image. A final link must select a non-overlapping section in the frozen layout and regenerate all branch encodings from that link map (`hardware-vad-trace/lifecycle-followup/late-publication/REPORT.md:39`; `hardware-vad-trace/native-poll-candidate/REPORT.md:77-83`).

The present source decision is therefore:

- **Proceed offline, conditionally:** poll wrapper, parser core, 32-byte response core, and late-publication constructor candidate, with the ABI and observed-startup assumptions stated above. Review the in-progress one-argument response shim and conditional loader once their reports are finalized.
- **Keep gated:** any production loader without a no-free/no-replace lifetime guarantee; any image link before all fixed reservations and hook targets are reconciled; any strict 32-byte wire claim before runtime framing inputs are bound; and any target or hardware qualification. Host checks and isolated CK803 assembly do not establish installed behavior.
