# Independent review: firmware integration builder and receipt

**Disposition:** the current decoded candidate and its receipt are structurally consistent with the pinned inputs and approved sparse edit set. The initial source-level no-clobber race is resolved by the helper reviewed below and its focused WSL/POSIX success/collision check. This review does not rerun the builder or rejection checks.

The initial builder source reviewed before the publication correction had SHA-256 `d230681b388d0f25436b64fa391667140f2c6fe8cfa00b7dda74eceac974234b`; the acceptance receipt SHA-256 is `551da1308d6791bd92d1d143f16494015e53efe18a2fbde1708c03722d41c84b`. I independently hashed the emitted decoded file: `ad86193a8a35a64d2ec036a5f32f6741a00ab4f29314b263205dc606db1b2ac0`, 1,243,776 bytes. It matches both `output.sha256` and `readback.sha256` in the receipt. All seven recorded input hashes also match the current files and the builder's pins.

The builder pins the frozen image, symbols, linker reservations, CK802 ELF, sparse hunk manifest, SDK symbols, and link receipt; it separately pins the decoder and objdump. It requires the sparse manifest's unapplied/non-installable status, exact CK802 profile, binding to the frozen image and ELF, the exact ten approved hunk tuples, 28 instruction bytes, and 124 excluded zero padding bytes. It checks each hunk's baseline preimage and corresponding ELF bytes, validates hunk and module placement against the frozen image and parser/upload/restore reservation ranges, and rejects nonzero constructor padding. Its header guard requires the baseline checksum/size fields to be zero and the on-disk readback must retain all 48 header bytes unchanged.

The receipt records 22 changed bytes in the baseline region, all inside the approved hunk extents; zero changed bytes outside those extents; a 3,584-byte zero gap; the exact 2,684-byte `.vad_text`; and four zero alignment bytes. Its module range ends at `0x0112fa7c`; the candidate ends at `0x0112fa80`. The previous independent root-assembly review already checked the same immutable decoded image and its packed structural artifact; this report only adds review of the builder source and receipt.

The initial review found a source-level no-clobber race at `build_candidate.py:449-450`: `os.rename(partial, final)` could replace a destination created after the preceding absence check on WSL/POSIX. The follow-up below verifies the replacement with an atomic no-clobber helper for both accepted and `.REJECTED` publication paths.

The receipt is schema 1 for an offline candidate; it is not the packer contract `h1e-vad-candidate-manifest-v1`. At this review an explicit adapter was still needed. The integration owner subsequently delivered `../firmware-container/adapt_vad_manifest.py` and a fresh successful container readback through it; see that folder's README and retained receipts. Those close the offline handoff and outer-container integrity boundary. Actual partition capacity and combined placement, lifetime/ROM/interrupt consumers, allocator alignment and success, target execution/response behavior, and hardware validation remain unproven or blocked. The candidate remains `NOT_INSTALL`.

## Follow-up: no-clobber publication race resolved

The builder now routes both final-candidate and `.REJECTED` publication through `publish_no_clobber()`: `os.link(partial, destination)` creates the destination atomically and `os.unlink(partial)` runs only after that succeeds. The focused `verify_publication.py` check exercised the production helper on the same POSIX filesystem used by `OUT`. Its recorded success case published the bytes and removed the partial name; final-name and `.REJECTED` collision cases raised `FileExistsError` while preserving both the competing destination bytes and the owned partial bytes. See `PUBLICATION-VERIFICATION.md` for the command and recorded evidence.

This resolves the source-level race identified above for the documented WSL/POSIX path. This follow-up only inspected the changed helper and its focused evidence; it did not rerun the candidate builder or rejection suite, rehash the previously reviewed candidate, or use hardware. The earlier decoded-image and packed-container structural proof remains bounded to the same pinned candidate and does not change the blocked production gates.
